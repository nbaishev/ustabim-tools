# Предварительные HTTP API-контракты

Контракты описывают будущий серверный API Next.js. Бизнес-endpoints пока не реализованы и требуют проверенной Supabase-сессии. Явно обозначенные operational health и auth callback endpoints являются исключениями и не работают с прикладными пользовательскими данными. API endpoints используют JSON, кроме прямой загрузки по signed URL; auth callback отвечает redirect. `X-Request-Id` будет добавлен общей middleware. Идентификаторы имеют формат UUID.

## Общие соглашения

Успешный ответ содержит объект `data`, список — `data` и `meta.nextCursor`. Создание возвращает `201`, чтение/изменение — `200`, успешное удаление — `204`. Для условной идемпотентности клиент передаёт заголовок `Idempotency-Key`; повтор с тем же пользователем, endpoint и эквивалентным телом возвращает исходный результат, а с другим телом — `VALIDATION_ERROR`.

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Безопасное сообщение для пользователя",
    "requestId": "uuid"
  }
}
```

Основные коды:

| Код | Типичный HTTP-статус | Значение |
|---|---:|---|
| `UNAUTHORIZED` | 401 | Сессия отсутствует или недействительна |
| `FORBIDDEN` | 403 | Сессия действительна, но операция не разрешена |
| `NOT_FOUND` | 404 | Ресурс отсутствует или скрыт политикой доступа |
| `VALIDATION_ERROR` | 400/409 | Параметры, тело, состояние или ключ идемпотентности недопустимы |
| `FILE_TOO_LARGE` | 413 | Размер превышает настроенный предел |
| `UNSUPPORTED_FILE_TYPE` | 415 | Тип или сигнатура файла не поддерживается |
| `RATE_LIMIT_EXCEEDED` | 429 | Превышена частота/квота запросов |
| `PROCESSING_FAILED` | 422/500 | Фоновая обработка завершилась ошибкой |
| `MODEL_ERROR` | 502/503 | Модель недоступна или вернула неприемлемый ответ |
| `INTERNAL_ERROR` | 500 | Непредвиденная серверная ошибка |

Все endpoints могут вернуть `UNAUTHORIZED`, `RATE_LIMIT_EXCEEDED` и `INTERNAL_ERROR`; ресурсные endpoints также возвращают `FORBIDDEN` или безопасный `NOT_FOUND`. `user_id` из тела игнорируется: сервер определяет пользователя по сессии. Строковые поля обрезаются, имеют явные лимиты; неизвестные поля отклоняются.

## Operational health

### `GET /api/health/supabase`

- **Назначение:** проверить доступность Auth API настроенного Supabase-проекта без чтения пользовательских данных.
- **Авторизация и параметры:** сессия, параметры пути, query и тело не требуются.
- **Успех:** `200 { "data": { "service": "supabase", "status": "connected" } }`.
- **Диагностические состояния:** `200` с безопасным статусом `not_configured`, `misconfigured` или `unavailable` в том же формате; endpoint предназначен для UI-диагностики, поэтому результат соединения передаётся в поле `status`, а URL, ключ, версия GoTrue и внутренний текст ошибки не возвращаются.
- **Доступ:** endpoint вызывает только фиксированный health URL из проверенной сервером конфигурации и не принимает адрес от клиента.
- **Идемпотентность:** GET идемпотентен; ответ имеет `Cache-Control: private, no-store`.

## Auth callback

### `GET /auth/callback`

- **Назначение:** одноразово обменять Supabase PKCE `code` регистрации, восстановления или Google OAuth на cookie-сессию.
- **Параметры:** query `code`; точное `next=/app` без `flow` для signup, `next=/reset-password` для recovery либо `flow=oauth` с внутренним `next=/app` или `/app/*` для Google; тело и исходная сессия не требуются.
- **Успех:** `307` redirect на `/app?reason=email-confirmed`, безопасный OAuth `next` или `/reset-password` с защищёнными cookies Supabase.
- **Ошибка:** `307` redirect на `/register?error=invalid-link`, `/forgot-password?error=invalid-link` или `/login?error=oauth` согласно потоку; техническая причина не раскрывается.
- **Доступ:** произвольные внешние `next` отклоняются, поэтому endpoint нельзя использовать как open redirect.
- **Идемпотентность:** code одноразовый; повторное использование приводит к безопасному error redirect.

## Проекты

### `GET /api/projects`

- **Назначение:** постранично вернуть проекты текущего пользователя.
- **Параметры:** query `cursor?`, `limit?` (1–100), `role?`; параметров пути и тела нет.
- **Успех:** `200 { "data": [{ "id", "name", "description", "ownerId", "role", "createdAt", "updatedAt" }], "meta": { "nextCursor" } }`; текущий выпуск возвращает полный список без пагинации.
- **Доступ:** запрос ограничивается RLS проектами, которыми пользователь владеет или где он активный участник.
- **Ошибки:** общие ошибки и `VALIDATION_ERROR` для неверной пагинации.
- **Идемпотентность:** GET идемпотентен; ключ не требуется.

### `POST /api/projects`

- **Назначение:** создать проект и назначить текущего пользователя владельцем.
- **Тело:** `{ "name": "string", "description": "string|null" }`; `ownerId` не принимается.
- **Успех:** `201 { "data": { "id", "name", "description", "ownerId", "role", "createdAt", "updatedAt" } }`.
- **Доступ:** любой авторизованный пользователь в пределах своей квоты; владелец выводится из сессии.
- **Ошибки:** общие, `VALIDATION_ERROR`.
- **Идемпотентность:** поддерживается и рекомендуется с `Idempotency-Key`.

### `GET /api/projects/{projectId}`

- **Назначение:** вернуть проект и роль текущего пользователя.
- **Путь:** `projectId` — UUID; тела нет.
- **Успех:** `200 { "data": { "id", "name", "description", "ownerId", "role", "createdAt", "updatedAt" } }`.
- **Доступ:** владелец или активный участник проекта; проверка сервером и RLS.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`, `VALIDATION_ERROR` для UUID.
- **Идемпотентность:** GET идемпотентен.

### `PATCH /api/projects/{projectId}`

- **Назначение:** изменить имя или описание проекта.
- **Путь/тело:** `projectId`; непустое `{ "name"?: "string", "description"?: "string|null" }`.
- **Успех:** `200 { "data": { "id", "name", "description", "ownerId", "updatedAt" } }`.
- **Доступ:** владелец или участник с ролью редактора; смена владельца этим endpoint запрещена.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`, `VALIDATION_ERROR`.
- **Идемпотентность:** PATCH с одинаковым телом идемпотентен; ключ необязателен.

### `DELETE /api/projects/{projectId}`

- **Назначение:** закрыть доступ к проекту и поставить удаление связанных данных в очередь.
- **Путь:** `projectId`; тела нет.
- **Успех:** `204` без тела после фиксации логического удаления/задачи очистки.
- **Доступ:** только владелец проекта; активные фоновые операции безопасно отменяются или завершаются без публикации.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`.
- **Идемпотентность:** повторное DELETE возвращает `204`; физическая очистка идемпотентна.

## Файлы проекта

### `POST /api/projects/{projectId}/files/upload-url`

- **Назначение:** создать запись файла в `uploading` и краткоживущую signed URL для прямой загрузки в приватный Storage.
- **Путь/тело:** `projectId`; `{ "fileName": "string", "contentType": "string", "sizeBytes": 123, "checksum": "string|null" }`.
- **Успех:** `201 { "data": { "fileId", "uploadUrl", "expiresAt", "requiredHeaders": {} } }`; URL не логируется.
- **Доступ:** участник с правом добавлять файлы; сервер проверяет проект, квоту, размер и тип до подписи пути.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`, `VALIDATION_ERROR`, `FILE_TOO_LARGE`, `UNSUPPORTED_FILE_TYPE`.
- **Идемпотентность:** обязательна для клиента; повтор возвращает тот же незавершённый upload, пока URL действителен, либо новую URL для той же записи.

### `GET /api/projects/{projectId}/files`

- **Назначение:** вернуть метаданные файлов проекта без постоянных публичных URL.
- **Параметры:** `projectId`; query `cursor?`, `limit?`, `status?`, `type?`; тела нет.
- **Успех:** `200 { "data": [{ "id", "originalName", "contentType", "sizeBytes", "status", "createdAt" }], "meta": { "nextCursor" } }`.
- **Доступ:** любой активный участник проекта; RLS исключает чужие файлы.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`, `VALIDATION_ERROR`.
- **Идемпотентность:** GET идемпотентен.

### `DELETE /api/projects/{projectId}/files/{fileId}`

- **Назначение:** логически удалить файл и поставить удаление объекта/производных данных в очередь.
- **Путь:** `projectId`, `fileId`; тела нет.
- **Успех:** `204` без тела.
- **Доступ:** владелец файла, редактор или владелец проекта; сервер проверяет, что файл принадлежит указанному проекту.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`; конфликт состояния — `VALIDATION_ERROR`.
- **Идемпотентность:** повторное удаление возвращает `204`.

## Чат

### `POST /api/chat/message`

- **Назначение:** отправить одно сообщение текущего пользователя в n8n-agent без сохранения истории.
- **Тело:** `{ "content": "string" }` после trim, от 1 до 8000 символов; неизвестные поля отклоняются.
- **Успех:** `200 { "data": { "answer": "string" } }`.
- **Доступ:** требуется проверенная Supabase-сессия. Сервер не принимает `userId`, проект или файлы и единолично подписывает запрос n8n.
- **Ошибки:** `UNAUTHORIZED`, `VALIDATION_ERROR`, `MODEL_ERROR`; внутренние адреса, ключи и текст ошибки модели не возвращаются.
- **Идемпотентность:** не поддерживается в первом синхронном выпуске; UI не допускает параллельную повторную отправку.

### `POST /api/chat/chats`

- **Назначение:** создать чат текущего пользователя, опционально в проекте.
- **Тело:** `{ "projectId": "uuid|null", "title": "string|null" }`.
- **Успех:** `201 { "data": { "id", "userId", "projectId", "title", "createdAt" } }`.
- **Доступ:** пользователь всегда становится владельцем; при `projectId` требуется активное членство.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`, `VALIDATION_ERROR`.
- **Идемпотентность:** поддерживается с `Idempotency-Key`.

### `GET /api/chat/chats`

- **Назначение:** вернуть чаты текущего пользователя.
- **Параметры:** query `projectId?`, `cursor?`, `limit?`; тела нет.
- **Успех:** `200 { "data": [{ "id", "projectId", "title", "lastMessageAt", "createdAt" }], "meta": { "nextCursor" } }`.
- **Доступ:** только `chats.user_id` текущего пользователя; проектный фильтр дополнительно проверяется.
- **Ошибки:** общие, `FORBIDDEN`, `VALIDATION_ERROR`.
- **Идемпотентность:** GET идемпотентен.

### `GET /api/chat/chats/{chatId}`

- **Назначение:** вернуть чат и страницу его сообщений с вложениями и разрешёнными источниками.
- **Параметры:** `chatId`; query `messageCursor?`, `limit?`; тела нет.
- **Успех:** `200 { "data": { "id", "projectId", "title", "messages": [], "nextMessageCursor" } }`.
- **Доступ:** только владелец чата и, для проектного чата, действующий участник проекта; источники чужих файлов скрываются.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`, `VALIDATION_ERROR`.
- **Идемпотентность:** GET идемпотентен.

### `DELETE /api/chat/chats/{chatId}`

- **Назначение:** логически удалить чат и прекратить активную генерацию.
- **Путь:** `chatId`; тела нет.
- **Успех:** `204` без тела.
- **Доступ:** только владелец чата.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`.
- **Идемпотентность:** повтор возвращает `204`.

### `POST /api/chat/chats/{chatId}/messages`

- **Назначение:** сохранить пользовательское сообщение и безопасно инициировать генерацию через n8n.
- **Путь/тело:** `chatId`; `{ "content": "string", "attachmentFileIds": ["uuid"] }`.
- **Успех:** `202 { "data": { "userMessage": { "id", "status" }, "assistantMessage": { "id", "status": "pending" } } }`; поток/опрос будет определён при реализации.
- **Доступ:** владелец чата; для проектного чата сохраняется доступ к проекту, а каждый attachment принадлежит ему и доступен пользователю. Сервер подписывает внутренний вызов n8n.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`, `VALIDATION_ERROR`, `MODEL_ERROR` для синхронного отказа запуска.
- **Идемпотентность:** `Idempotency-Key` обязателен, чтобы повтор не создал сообщение и платный вызов повторно.

## Геология

### `POST /api/projects/{projectId}/geology/jobs`

- **Назначение:** создать фоновое задание анализа конкретного PDF.
- **Путь/тело:** `projectId`; `{ "fileId": "uuid" }`.
- **Успех:** `202 { "data": { "id", "projectId", "fileId", "status": "uploaded", "attempt", "createdAt" } }`.
- **Доступ:** участник с правом запуска анализа; файл должен принадлежать проекту, иметь поддерживаемый PDF-тип и готовый статус. Запуск n8n выполняется только сервером.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`, `VALIDATION_ERROR`, `FILE_TOO_LARGE`, `UNSUPPORTED_FILE_TYPE`.
- **Идемпотентность:** `Idempotency-Key` обязателен; активное эквивалентное задание возвращается повторно, новый анализ завершённого файла требует нового ключа.

### `GET /api/projects/{projectId}/geology/jobs/{jobId}`

- **Назначение:** вернуть состояние, прогресс и безопасную ошибку задания.
- **Путь:** `projectId`, `jobId`; тела нет.
- **Успех:** `200 { "data": { "id", "fileId", "reportId", "status", "progress", "attempt", "error": null, "updatedAt" } }`.
- **Доступ:** активный участник проекта; job обязательно принадлежит `projectId`.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`, `PROCESSING_FAILED` не заменяет чтение записи, а отражается в её статусе.
- **Идемпотентность:** GET идемпотентен.

### `GET /api/projects/{projectId}/geology/reports/{reportId}`

- **Назначение:** вернуть структурированный отчёт, параметры, выводы и ссылки на страницы-источники.
- **Параметры:** `projectId`, `reportId`; query `include?`; тела нет.
- **Успех:** `200 { "data": { "id", "sourceFileId", "status", "summary", "boreholes": [], "elements": [], "parameters": [], "findings": [] } }`.
- **Доступ:** участник проекта; отчёт и его исходный файл должны принадлежать тому же проекту.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`, `VALIDATION_ERROR`.
- **Идемпотентность:** GET идемпотентен.

### `PATCH /api/projects/{projectId}/geology/parameters/{parameterId}`

- **Назначение:** сохранить ручную коррекцию значения без изменения исходного извлечённого значения.
- **Путь/тело:** `projectId`, `parameterId`; `{ "correctedValue": "string|number|null", "correctedUnit": "string|null", "reason": "string" }`.
- **Успех:** `200 { "data": { "id", "rawValue", "rawUnit", "correctedValue", "correctedUnit", "correctedBy", "correctedAt" } }`.
- **Доступ:** участник с ролью редактора/reviewer; параметр принадлежит отчёту проекта. `rawValue`, источники и автор коррекции не принимаются от клиента.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`, `VALIDATION_ERROR`.
- **Идемпотентность:** одинаковая коррекция идемпотентна; каждая фактическая смена записывается в audit log.

## Калькуляторы

### `GET /api/calculators`

- **Назначение:** вернуть активные определения калькуляторов и схемы их входов.
- **Параметры:** параметров пути и тела нет; допускается query `cursor?`, `limit?`.
- **Успех:** `200 { "data": [{ "slug", "name", "description", "algorithmVersion", "inputSchema" }], "meta": { "nextCursor" } }`.
- **Доступ:** любой авторизованный пользователь; выдаются только активные безопасные определения.
- **Ошибки:** общие, `VALIDATION_ERROR`.
- **Идемпотентность:** GET идемпотентен.

### `POST /api/calculators/{calculatorSlug}/run`

- **Назначение:** валидировать вход, выполнить точный версионированный алгоритм и сохранить запуск.
- **Путь/тело:** `calculatorSlug`; `{ "projectId": "uuid|null", "input": {} }`, где `input` соответствует опубликованной схеме.
- **Успех:** `200` для немедленного расчёта или `202` для фонового: `{ "data": { "id", "calculatorSlug", "algorithmVersion", "status", "input", "output", "createdAt" } }`.
- **Доступ:** авторизованный пользователь; при `projectId` требуется членство. Алгоритм выполняет web backend, не n8n.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`, `VALIDATION_ERROR`.
- **Идемпотентность:** `Idempotency-Key` обязателен; сохраняются точные входы и версия алгоритма.

### `GET /api/calculator-runs/{runId}`

- **Назначение:** вернуть сохранённый запуск и его результат/безопасную ошибку.
- **Путь:** `runId`; тела нет.
- **Успех:** `200 { "data": { "id", "calculatorSlug", "algorithmVersion", "projectId", "status", "input", "output", "error", "createdAt" } }`.
- **Доступ:** владелец запуска; для проектного запуска также действуют права проекта согласно будущей роли.
- **Ошибки:** общие, `NOT_FOUND`, `FORBIDDEN`, `PROCESSING_FAILED` отражается статусом записи.
- **Идемпотентность:** GET идемпотентен.

## Внутренние вызовы

Публичные контракты не раскрывают адреса n8n и workers. Серверные вызовы включают `requestId`, проверенный `userId`, идентификатор проекта/операции, timestamp, nonce и подпись тела. Получатель проверяет подпись и срок действия, а результат записывает по идентификатору операции идемпотентно. Технические ответы внутренних сервисов никогда не проксируются клиенту дословно.
