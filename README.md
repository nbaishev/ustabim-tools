# UstaBIM Tools

UstaBIM Tools — будущий самостоятельный инженерный веб-сервис для работы с BIM-моделями, расчётами и инженерными документами. Планируемый адрес сервиса: `https://tools.ustabim.online`. Существующий сайт `ustabim.online` позднее будет содержать только ссылку на этот сервис.

Проект находится на этапе подготовки архитектурной основы. Репозиторий пока содержит документацию, общие статусы и заготовки каталогов; пользовательские функции не реализованы.

> Инженерные расчёты и результаты анализа геологических отчётов являются вспомогательными и должны проверяться квалифицированным специалистом.

## Планируемые возможности

- личный кабинет и проекты пользователя;
- безопасная загрузка и хранение файлов;
- браузерный IFC-просмотрщик;
- инженерные калькуляторы;
- ИИ-чат с историей и RAG;
- анализ геологических PDF-отчётов.

## Архитектура

Пользовательский интерфейс и серверный API планируются на Next.js. Supabase будет отвечать за авторизацию, PostgreSQL, RLS и приватное файловое хранилище. ИИ-чат и оркестрация анализа геологии будут вынесены в отдельные n8n workflow. Обработка документов и будущий серверный анализ IFC будут выполняться Python workers. IFC-модель будет отображаться в браузере средствами That Open Components и web-ifc.

Браузер не обращается к приватным webhook n8n напрямую: запрос проходит через серверную часть web-приложения после проверки сессии и доступа к проекту. Подробности приведены в [архитектуре](docs/architecture.md).

## Структура репозитория

```text
apps/web/                  Будущее Next.js-приложение и общие TypeScript-типы
services/document-worker/ Будущий сервис извлечения данных из PDF
services/ifc-worker/      Будущий сервис серверной обработки IFC
n8n/chat/                 Будущие workflow ИИ-чата
n8n/geology/              Будущие workflow анализа геологии
n8n/shared/               Общие заготовки и соглашения n8n
supabase/migrations/      Будущие SQL-миграции Supabase
supabase/seed/            Будущие тестовые данные
docs/                     Архитектурная и контрактная документация
docker-compose.yml        Заготовка локальной инфраструктуры
```

## Предполагаемый локальный запуск

На текущем этапе запускать приложение нечего. После появления реализаций предполагается следующий порядок:

1. Создать локальный `.env` по образцу `.env.example`, не добавляя его в Git.
2. Подготовить внешний проект Supabase; локальный Supabase в текущий Compose не входит.
3. Запустить инфраструктуру n8n, PostgreSQL и Redis командой `docker compose --profile automation up`.
4. Отдельно запустить реализованные workers, затем web-приложение.
5. Проверить доступность компонентов и только после этого импортировать будущие n8n workflow.

Текущий `docker-compose.yml` описывает лишь будущую локальную инфраструктуру. Workers представлены метаданными-заглушками и не запускаются.
